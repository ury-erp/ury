# Open Questions — URY Approval & Control System

The following points are ambiguous or conflict with the audited code. Work affected by each answer should not be guessed.

1. **Missing v15 source (blocks Item price-control port and purchase price approval).** `upstream/version-15` contains none of the specified Item price-control fields or logic, and no matching implementation was found in repository history. Which branch/commit contains the feature to port? If it does not exist, should the Item-level design in this specification be implemented as new work instead?
2. **Approver identity and default roles (blocks final branch schema/routing).** Should an approver be a User, a Role, or either? Are “Restaurant Manager” and “Finance Head” new URY roles, existing ERPNext roles, or configurable User/Role links? What are the default purchase/expense/backdated approvers, and where is the self-approval setting stored (branch or global)?
3. **Branch buying price list (blocks purchase comparison).** Should the branch's buying Price List be a new Branch field, or should each purchase document's native `buying_price_list` take precedence? How should validity dates, supplier-specific Item Prices, UOM, and currency conversion be handled?
4. **Purchase document coverage (blocks purchase hooks).** Does “purchase document” mean Purchase Order, Purchase Receipt, and Purchase Invoice, or only Purchase Invoice? Should Material Request be included?
5. **Expense DocTypes and account mapping (blocks expense/budget approval).** Does “Expense” mean HRMS Expense Claim, Purchase Invoice, Journal Entry, URY Fixed/Variable Expenses, or all of these? For Employee Advance, which expense account and cost center select the Budget: the advance account (normally a balance-sheet account and therefore not a native Budget account), employee/department defaults, or new branch/document fields?
6. **Reservation timing (blocks budget concurrency design).** Should a URY budget reservation be created on draft save, first approval request, final approval, or submission? How should a warning-only save behave, and how long may stale draft reservations remain?
7. **Backdated transaction coverage and finalization source (blocks period control).** Which DocTypes does “all entries” include (all submittable accounting/stock documents, Journal Entry, Payment Entry, invoices,Expense Claim, Employee Advance)? Is monthly P&L finalization a new URY Period Lock action independent of URY Daily P and L, or must daily P&L records all be submitted first? How is the Finance Head identified?
8. **Mixed-branch source of truth (blocks mixed-branch validation).** Should row branches be derived from each row's Cost Center and Warehouse, or require explicit branch custom fields on parent/rows? For documents without a branch today, is a required parent `branch` field acceptable even when URY controls are disabled?
9. **UPI classification (blocks payment routing).** ERPNext Mode of Payment normally classifies Cash/Bank/Phone/General. Should UPI be configured by explicit Mode of Payment links per branch/rule, by name, or by a custom payment-type field?
10. **Approval workflow execution (blocks approver UX but not core data model).** May approval decisions use a URY whitelisted server API that enforces configured User/Role and level rules while the ERPNext Workflow records the same states, or must users execute native Workflow transitions directly? Native Workflow transitions are role-based and cannot by themselves express arbitrary per-branch User approvers.
11. **Final push destination.** Per instruction, `origin` is not configured; remotes remain `upstream` (`ury-erp/ury`) and `fork` (`ashique-tridz/ury`). At completion, should `git push -u fork feature/approval-control-system-v16` be used instead of the specification's `origin` command?
