# موقع المطعم والحجز الإلكتروني

وحدة داخل Smart Restro / URY، بتصميم عام للزوار ولوحة محتوى في Frappe Desk.
الرابط العام: `/restaurant?slug=smart-choice`، ورابط الإدارة: `/app/ury-website`.
تظهر وصلة «موقع المطعم» للمدير في الشريط الجانبي بعد بناء واجهة الإدارة ونشرها.

## ما تم تنفيذه

- تصميم متجاوب يدعم العربية RTL والإنجليزية، مع خطوط عربية محلية، وثلاث هويات لونية: زيتوني، طيني، أزرق داكن.
- إدارة الشعار والغلاف والعناوين والحكاية والصور والعنوان والهاتف وروابط الخريطة وإنستغرام.
- عرض المنيو الحقيقي من `URY Menu` مع الأسعار، البحث، تصنيفات الأصناف، واختيار الشيف؛ لا يعرض تكاليف التحضير أو الأصناف المعطّلة.
- إعداد أوقات العمل لكل يوم، بما فيها العمل بعد منتصف الليل، ومدة الجلسة والمهلة الدنيا للحجز وحدّ الأشخاص والأيام.
- اختيار التاريخ والوقت والأشخاص، ثم عرض الطاولات حسب القاعة بالحالات: متاحة، محجوزة، غير متاحة. العرض بطاقات بصرية وليس مخططاً هندسياً للصالة.
- تحديث توفر الطاولات كل 30 ثانية أثناء استخدام الصفحة، وإعادة التحقق قبل التسجيل.
- إرسال طلب باسم الزبون ورقم هاتفه وملاحظاته وموافقته على استخدام البيانات للحجز.
- الحجز يُحفظ في `URY Table Reservation` بالحالة `Requested`، ويُدار من شاشة الحجوزات الموجودة. لا يُعد مؤكداً قبل اعتماد الموظف.
- صفحة نجاح برقم الطلب، وحماية من تسجيل طلب مكرر عند إعادة الإرسال بعد انقطاع الاتصال.
- معاينة خاصة للمدير قبل النشر، وعنوان ووصف SEO وبيانات مشاركة اجتماعية.

## إدارة الصفحة

1. افتح «موقع المطعم» وأنشئ سجلاً. اختر المطعم، وأدخل الاسم ورابطاً قصيراً بأحرف إنجليزية وأرقام وشرطات.
2. اختر اللغة والألوان وارفع الصور كملفات عامة. اكتب محتوى المطعم الحقيقي؛ حقول الغلاف والحكاية لا تسمح بإدخال JavaScript أو CSS مخصص.
3. اختر المنيو أو اتركه فارغاً لاستخدام المنيو الافتراضي للمطعم. يمكن إخفاء المنيو أو الحكاية.
4. أدخل أوقات العمل الحقيقية. اليوم غير المدرج مغلق. إذا كان الإغلاق قبل الفتح فهو في اليوم التالي.
5. اضبط مدة الجلسة والسياسة، ثم فعّل استقبال الحجوزات عند الجاهزية. لا تُقبل جلسة يمتد وقتها بعد الإغلاق.
6. احفظ واستخدم «معاينة الموقع». المعاينة تتطلب صلاحية التعديل ولا تستقبل حجوزات.
7. فعّل `Published` لنشر المحتوى؛ إلغاء تفعيله يغلق الصفحة والواجهات العامة للحجز.

لعدة فروع، أنشئ صفحة لكل سجل مطعم. هذا الإصدار لا يتضمن اختيار عدة فروع داخل صفحة واحدة أو محرراً بالسحب والإفلات أو دفع العربون أو رسائل واتساب تلقائية.

## التوفر والتعارض

الطاولة يجب أن تتبع المطعم والفرع المحددين، وأن تلائم الحد الأدنى والأقصى للجلوس، وألا تكون مدموجة أو محجوزة في الفترة المطلوبة. الطاولات المشغولة تُحجب للحجوزات القريبة خلال نافذة الجلسة المقدّرة. حالتها الحالية ليست وحدها معيار حجز الأيام المقبلة.

الحجوزات التي أدخلها الموظف دون تخصيص طاولة تمنع بيع طاولات إضافية إلكترونياً في الفترة المتقاطعة، إلى أن يخصص لها الموظف طاولات. هذا سلوك تحفظي مقصود لمنع الوعد بسعة غير مضمونة.

الحجز من الموقع والموظفين يشتركان في قفل على سجل الفرع وفحص تقاطع زمني بقفل قراءة حالي. تُنفّذ عملية التحقق والإدخال ضمن معاملة واحدة. الحجز العام يفرض السعة بشكل صارم؛ تبقى مرونة زيادة الكراسي للموظفين كما في النظام الحالي.

تعرض الواجهة العامة بيانات الطاولة فقط، ولا تعرض أسماء أصحاب الحجوزات أو أرقامهم. طلبات التوفر محدودة بـ60 طلباً/دقيقة لكل IP، وطلبات التسجيل بـ8 طلبات/ساعة. تتضمن الكتابة CSRF وحقلاً لكشف الطلبات الآلية ومعرّفاً فريداً لإعادة الإرسال. عند فقدان رد التسجيل تقفل الواجهة التفاصيل وتتيح إعادة إرسال الطلب نفسه للتحقق دون تكرار.

## التفعيل على موقع Frappe

تتطلب هذه الخطوة إذناً بتعديل قاعدة بيانات الموقع المستهدف. لم تُنفّذ على `demo.smarterp.com` لأن المراجعة التلقائية رفضت النشر دون موافقة صريحة.

حمّل النماذج بهذا الترتيب باستخدام `frappe.reload_doc('ury', 'doctype', name, force=True)` من جلسة إدارة مصرح بها:

1. `ury_website_image`
2. `ury_website_hours`
3. `ury_website`
4. `ury_table_reservation` لإضافة حقل `website_request_id` الفريد.

لا يتطلب هذا تصدير بيانات أو استبدال سجلات الحجوزات. النماذج الجديدة محفوظة بالفعل كملفات JSON قياسية ضمن التطبيق. بعد التحميل تُحفظ المعاملة وتُحدّث ذاكرة الموقع، ويُنشر بناء واجهة الإدارة لتظهر الوصلة الجديدة. ملفات CSS وJavaScript العامة تُخدم من `/assets/ury/`.

قبل فتح الحجز للجمهور، اختبر كتابة حجز واعتماده وإلغاءه والتزامن في بيئة اختبار مخصصة. لم تُجرَ اختبارات كتابة أو ترحيل على قاعدة البيانات المشتركة في هذه المهمة.

## التحقق المحلي

```bash
# من مجلد التطبيق، باستخدام Python الخاص بالـbench
../../env/bin/python -m unittest ury.ury.api.test_restaurant_website -v
../../env/bin/python scripts/preview_restaurant_website.py

# Playwright مثبت مسبقاً في هذه البيئة؛ يمكن استخدام مسار تثبيت آخر
PLAYWRIGHT_PACKAGE=/tmp/ury-ux-browser/node_modules/playwright \
  node scripts/test_restaurant_website_browser.cjs
```

المعاينات واللقطات تُولّد في `/tmp/ury-restaurant-preview/`. جميع البيانات والمواعيد في المعاينة المحلية توضيحية. خيار `--site` في مولّد المعاينة يقرأ المنيو الحقيقي فقط، ولا ينشئ موقعاً أو حجزاً.

الاختبارات تغطي قواعد الوقت والخصوصية والتوفر والتكرار، وتجربة المتصفح بالعربية والإنجليزية بعرض 390 و1440 بكسل. نجح بناء الإدارة إلى مجلد مؤقت. فحص TypeScript الشامل متعثر بأخطاء موجودة في ملفات أخرى، منها `DynamicForm.tsx` وبعض صفحات التقارير؛ لم تُعدّل ضمن هذه الميزة.
