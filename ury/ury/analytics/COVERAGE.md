# URY restaurant analytics: coverage catalogue

Generated by `build_coverage.py` (do not edit by hand; rerun the script). Inputs: `metric_dictionary.json`, `dashboard_portfolio.md`, `dashboards/DB*.yaml`.

## Method (what counts as shown)

- A metric is SHOWN only if a chart that currently exists in a `dashboards/DB*.yaml` file is tied to it, either by that chart's row in `dashboard_portfolio.md` or by a `#` comment block directly above the chart in the YAML naming the metric id. Comments flagged T4 / not recorded / dropped are ignored. Charts listed in the portfolio but absent from the YAML do not count.
- Fallback trace (marked `~` after the chart id): when a YAML chart has no id tie by (a) or (b), a metric is attached if the chart's title or a y label equals/contains the metric name and the chart's query is one of the metric's source facts. Weaker evidence than an id tie.
- Level shown is inferred per chart from its grouping columns (x, rows, columns, split_by) and from dashboard filters whose `applies_to` names the chart's query (branch, waiter = employee, department, category, item). Company comes from the DB's `Levels:` line in the portfolio. This is a chart-level inference, not a per-metric guarantee.
- Theme matrix: metric prefix -> theme (MAR margin; PRD, PLN production; WST, STK wastage; YLD yield; KIT, TBL timing; SAL, MNU, PAY sales; EMP people). LKG (leakage) and DQ (data quality) metrics belong to no requested theme and are excluded from the matrix. A cell counts a DB only if one of its charts shows a metric of that theme at that level and the dictionary lists that level for the metric.
